Why SentinelAI needs a staged design

Medical-device reports are noisy, terminology-bound, privacy-sensitive, and require auditable human oversight.
Noisy free text
Reports mix device issues, patient outcomes, timelines, and vague wording.
Broad candidate search
Controlled terminology
The output must be a valid MedDRA term, not a free-form summary.
Search within vocabulary
Exact words + paraphrases
Some reports use the exact medical term; others describe it indirectly.
Lexical + semantic search
Ambiguous coding
Several MedDRA terms can be plausible for the same report.
Top-K + confidence
Privacy + regulation
Medical narratives should not be sent to open external APIs by default.
Local processing
Traceable accountability
Suggestions must be reviewable, stored, and correctable by a human.
Audit trail + human review
Therefore, SentinelAI uses a staged local funnel: candidate retrieval → careful comparison → constrained suggestion → human review
